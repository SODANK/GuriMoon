Reference — events, actions, body formatting

Events: roomEnter fires when the player warps into / loads this room · npcDamaged when the player first shoots a ball · npcKilled on ball death · roomCleared when the last hostile ball dies · gateActivated when an acceleration gate in this room is used · itemPlaced when a pilot drags an item from their cargo hold into a container ball. Name the ball and the item, and a quantity if it takes more than one: the count is what the container holds, so several drops add up. A container takes items only while an itemPlaced trigger listens to it, and the pilot can take them back out. (The event names are the stored wire values — everything in space is a ball.) Actions: transmission = the TRANSMISSIONS popup window · localChat = a narrator line in Local (body text only, no sender) · popup = plain message box · spawnWave = spawn this room's balls assigned to that wave group (set Wave per ball below or in the 3D editor; wave balls stay hidden until their wave spawns) · completeDungeon = finish the site: a mission's objective is met, an open site starts its clear countdown. Rats still alive stay. A kill-item mission still wants its item delivered · music = crossfade the pilot's music to a track, the same switch a gate's dunMusicUrl makes. With roomEnter it plays as the ship lands; when the track ends the normal playlist resumes. A pilot who has stopped or paused their music hears nothing. Chain waves with several once-only roomCleared → spawnWave triggers: each clear releases the next unfired wave in order. One event can run several actions: add a trigger per action, for example an itemPlaced that spawns a wave and a second one on the same ball and item that speaks a localChat line.

Transmission Icon = an eveGraphics graphicID (its icon string is used; corp-logo sheet icons show corp logos). Transmission body is HTML — embed client images inline: <img src=corplogo:1000125 width=64 height=64>, typeicon:587, portrait:<charID>, icon:38_14. Defer holds the popup until the player drops out of warp (client-side [d] header prefix).

Local chat body is plain text and is always sent as a narrator line: the client prints the body only, with no Sender > prefix (The mercenary squad leader has arrived to face you!). Write the speaker into the text if you want one (EoM Priest: Purge the unbelievers!). Narrator lines are tinted cyan by the client unless a colour is set. Start the body with /emote to opt out and get a roleplay line instead (* Name does something), which does show the speaker name. The portrait square left of each line is a chat-window setting, not something the server sends — click the top compact mode button on the chat window to drop the picture column.

Ball Setup — name, wave, AI, faction, leash

Name is what the client shows in brackets, the overview and Show Info for this ball — the type is only the template, so a spawned Serpentis Scout can broadcast as Kruul's Bodyguard. Blank = the type's own name. Category 6 (player-hull Ships) is the one exception: the client always renders those by type name, so custom names on hull-category balls are ignored — use a category 11 Entity type. Wave 0 spawns the ball with the room; 1+ holds it back until a spawnWave trigger for that number fires. Leash anchors the ball to another ball in this room: with no target it flies a circle around that ball at Orbit metres instead of sitting still. Great for patrols around a structure. Invuln only applies to structures (Large Collidable Objects and Structures, spawn containers, sentry guns). Those are lockable and destructible by default; tick Invuln to nail one down as permanent scenery — it still locks and still eats fire, it just never loses HP. Structures never count toward a killAll objective either way, but one can still be named as a mission's target type. Solid makes a structure a collision sphere of its radius: ships bounce off it, and a warp line through it drops out of warp at its surface. On by default for everything except clouds, beacons and force fields. Rats always collide; scenery that is not a structure is set from its row in the objects table (or the 3D editor).

Reference — how drops work

Drops authored here belong to this ball in this dungeon, not to its item type — kill that ball, get that item. They roll on their own Chance (100% = guaranteed), skip the normal haul gate and the max-drops cap, and land in the same wreck can as the type/group loot tables. Use it for mission objective items and scripted flavour drops. Qty rolls between Min and Max. A blueprint always drops as one copy (ME 0 / PE 0), never an original: Min/Max are its runs, capped at the blueprint's own max runs. Destructible structures (containers, Overseer's structures, LCOs, sentries) are listed too and drop theirs where they die. An invulnerable structure never dies, so its list never drops.

Items dropped bounds how many different entries of a ball's list land per kill (blank = no bound). Each entry still rolls its own Chance first. Short of the minimum, entries that missed are added, picked by their Chance; over the maximum, extras are cut at random and 100% entries are kept first. A minimum above the number of entries just means every entry drops.

Copy and Paste move a whole list, Items dropped range included, to another ball in any room or dungeon. Paste replaces what the target had. The copy points at the source ball, so edits made to it before you paste carry over.
