Client Setup — Hosts File

The Blood 3913 client fetches news and billboard content from hardcoded hostnames. To redirect these requests to your server, add entries to the hosts file on each client machine.

Hosts file location:

  • Windows: C:\Windows\System32\drivers\etc\hosts (edit as Administrator)
  • Linux / macOS: /etc/hosts (edit with sudo)

Add these lines (replace SERVER_IP with your server’s IP, or 127.0.0.1 if running locally):

SERVER_IP    myeve.eve-online.com
SERVER_IP    img.eve.is
  • myeve.eve-online.com — news pages (/mb/news.asp), billboard ticker (/mb/news-headlines.asp), and billboard images (/bitmaps/billboards/)
  • img.eve.is — character portraits used by WANTED billboard posters (/serv.asp, /chr/serv.asp)

The news server must listen on port 80 (the client URLs carry no port). Configured via "newsListen": ":80" in config.json. Restart the server after changing config.

Articles are served to the game client at /mb/news.asp (character select screen) and /mb/news-headlines.asp (billboard ticker). The body is EVE-HTML — an old-HTML subset, not Markdown. Use the toolbar buttons below to insert tags. Insert <!--more--> (the ¶ button) to cut the list view there with a "» read more" link. Articles flagged Billboard Screen push their image onto in-space billboard screens (upload square images, 512×512 works best; clients refresh within ~60s).

Images

Uploaded files land in data/news-images/ and are served to the client at /img/<filename>. Use one as the article image (right-hand thumbnail), inline in the body via the Img toolbar button, or on billboards via the Billboard Screen flag.

  • Formats: JPG or PNG preferred; GIF works. BMP renders on news pages but cannot go on billboards.
  • Article thumbnail: shown 170px wide in the news list — roughly square to 4:3 looks right, any size accepted.
  • Inline body images: rendered at native pixel size in the client browser (~760px usable width at char select).
  • Billboard screen: the server rescales the flagged article's image to a 512×512 baseline JPEG automatically (the 3D screen requires power-of-two textures). Upload square or near-square — non-square images get stretched to fit. In-space screens refresh within ~60s.
  • WANTED portraits: separate system — drop <charID>_256.jpg files into data/portraits/; rescaled the same way.
