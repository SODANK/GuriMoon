Content Packages

How packages work

A package is one .gmpkg file holding dungeons (rooms, objects, object loot and Dungeon Logic), mission templates, open-site spawners and the custom NPC types they use with those NPCs' loot. Picking a mission adds its dungeon and the rest of its chain; picking a spawner adds its dungeon. On install every row gets a new ID on this server, so a package never overwrites existing content. A package must match the format exactly: an unknown file, column or value, a raw database ID, a number out of range or an install.sql that differs from the data rejects the whole file. Base game data (item types, factions, stations, regions) is referred to by ID and checked against this server before anything is written. Check package runs the whole install and rolls it back, so its report is exactly what Install will do. Installing a package that is already installed (same package ID) upgrades it in place: rows keep their IDs and enabled state, new rows are added and rows the new version dropped are removed. To publish an update of an installed package, pick it under Package when exporting. Uninstall removes exactly the rows the package installed; it is refused while players are in one of its dungeons.
